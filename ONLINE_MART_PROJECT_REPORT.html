Online-MART: Comprehensive Project Report

1. Project Overview

Online-MART is a full-stack, multi-role e-commerce platform designed for customers, retailers, wholesalers, and delivery agents. It features robust inventory management, order processing, proxy product listing, analytics, and real-time notifications, built with Next.js, Supabase, and PostgreSQL.

2. Key Features

  • Multi-role authentication: Customer, Retailer, Wholesaler, Delivery Person
  • Role-based dashboards and access control
  • Product browsing, search, filtering, cart, wishlist, and reviews
  • Order placement, tracking, and delivery assignment
  • Inventory management with low stock alerts
  • Proxy product system for retailers (list wholesaler products)
  • Business analytics for retailers and wholesalers
  • Automated email and in-app notifications
  • Support ticket and feedback system
  • Secure API with Row Level Security (RLS)
  • Responsive UI/UX

3. Architecture & Tech Stack

  • Frontend: Next.js (App Router), React, TypeScript, Tailwind CSS
  • Backend: Next.js API routes, Supabase (PostgreSQL, Auth, Storage)
  • Database: PostgreSQL (Supabase hosted)
  • Email: Resend, SendGrid, or AWS SES (configurable)
  • Authentication: Supabase Auth (JWT, OAuth, OTP)
  • CI/CD: Vercel (recommended)

4. Database & Model Alignment

All models (Product, User, Customer, Retailer, Wholesaler, Inventory, Feedback, etc.) are perfectly aligned with the database schema. Automated triggers ensure inventory consistency and order tracking. See MODEL_DB_ALIGNMENT.md for full details. 

CREATE TABLE products (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name text NOT NULL,
  description text,
  category_id uuid,
  sku text UNIQUE,
  base_price numeric,
  unit text DEFAULT 'piece',
  specifications jsonb DEFAULT '{}',
  is_active boolean DEFAULT true,
  created_at timestamptz DEFAULT now(),
  updated_at timestamptz DEFAULT now()
);

Other models (User, Customer, Cart, Category, Inventory, ProductImage) are similarly aligned.

6. Wholesaler Proxy System

Retailers can list wholesaler products as proxy items. Orders for proxy items are fulfilled from wholesaler inventory, with automated stock management and commission for retailers. The system uses dedicated tables and triggers for seamless operation. 

CREATE TABLE proxy_listings (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  retailer_id uuid NOT NULL,
  wholesaler_id uuid NOT NULL,
  wholesaler_inventory_id uuid NOT NULL,
  quantity_to_list integer NOT NULL,
  markup_percentage numeric DEFAULT 0,
  custom_price numeric,
  is_active boolean DEFAULT true,
  created_at timestamp with time zone DEFAULT now(),
  updated_at timestamp with time zone DEFAULT now(),
  UNIQUE(retailer_id, wholesaler_inventory_id)
);

Order flow for proxy items ensures correct inventory deduction and status tracking.

7. API Overview

  • Order Management: GET /api/orders, PATCH /api/orders/[id]
  • Retailer APIs: GET /api/retailer/stats, GET /api/retailer/analytics, GET /api/retailer/proxy-inventory
  • Wholesaler APIs: GET /api/wholesaler/inventory, GET /api/wholesaler/orders
  • General: GET /api/categories, POST /api/uploads, GET /api/feedback

8. Setup & Installation

  1. Clone the repository and install dependencies (npm install)
  2. Configure environment variables in .env.local
  3. Set up Supabase project and run SQL migration scripts in /scripts/
  4. Run the development server (npm run dev)
  5. Register as each user type to test all flows

See SETUP_INSTRUCTIONS.md for troubleshooting and environment setup details.

9. Testing & Validation

11. Security & Access Control

  • Service Role Key used only in server-side code

  • Role-based access for all APIs and dashboards
